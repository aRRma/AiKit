# arrma-kit

Скиллы и агенты для Claude Code. Агент работает маленькими шагами, после каждого шага его проверяют свежие субагенты, а чинится только то, что подтвердилось. От языка проекта набор не зависит: команды сборки и тестов берутся из `CLAUDE.md` проекта.

Наглядная шпаргалка: https://arrma.github.io/AiKit/GUIDE.html (или открой `GUIDE.html` в браузере).

## Цикл

```
/arrma-task-analysis <задача>  →  /arrma-recheck   (сколько угодно раз)
/arrma-task-plan               →  /arrma-recheck
/arrma-task-stage              →  /arrma-recheck   (так для каждого этапа)
```

`/arrma-recheck` сам понимает, что проверять: анализ, план или код этапа. Ответ «Новых стоящих находок нет, можно идти дальше» значит, что пора к следующему шагу. Между шагами делай `/clear`: всё состояние лежит в файлах задачи, а чистый контекст дешевле и точнее. Ответ на вопрос агента можно дописать к следующей команде: `/arrma-recheck Q1: делаем от main`.

## Установка

```powershell
New-Item -ItemType Directory -Force "$HOME/.claude/skills", "$HOME/.claude/agents", "$HOME/.claude/rules" | Out-Null
Copy-Item skills/* "$HOME/.claude/skills/" -Recurse -Force
Copy-Item agents/*.md "$HOME/.claude/agents/" -Force
Copy-Item rules/arrma.md "$HOME/.claude/rules/" -Force
```

1. Выполни команды в PowerShell из папки `arrma-kit`. Обновление делается ими же.
2. Удали старые версии без приставки `arrma-` и `spec-guard`, иначе скиллы сработают дважды. Если раньше вставлял правила в `~/.claude/CLAUDE.md`, убери их оттуда.
3. В `CLAUDE.md` каждого проекта напиши команды сборки, тестов затронутого кода и всех тестов, признаки сбоя среды (Docker, VPN, база), живые проверки, которых проект требует для области кода, и, если нужно, папку задач. Чего не хватает, покажет `/arrma-claude-md-check`.
4. Для русских имён файлов один раз: `git config --global core.quotepath false`.
5. Если в `~/.claude/CLAUDE.md` есть раздел «Стиль „по STE“» со строкой `@~/.claude/style-ru-ste.md`, удали раздел: теперь это скилл `arrma-ste`, он грузится только когда нужен.
6. Перезапусти Claude Code.

## Скиллы

| Команда | Когда | Что можно дописать |
|---|---|---|
| `/arrma-task-analysis` | новая задача | текст задачи, `model=`, `effort=` |
| `/arrma-task-plan` | нужен план или «упрости план» | ответ на вопрос |
| `/arrma-task-stage` | сделать один этап | номер этапа |
| `/arrma-recheck` | после любого шага | ответ или замечание, `model=`, `effort=` |
| `/arrma-task-status` | спросить, что сделано и что дальше; коротко, ничего не запускает | название задачи |
| `/arrma-verify-claims` | проверить утверждение или документацию по коду | что проверить, `model=`, `effort=` |
| `/arrma-task-summary` | описание готовой задачи из пяти блоков: проблема, что сделано, ожидаемое поведение, как проверить, как выкатить | `md` или `redmine`; `dev` — для разработчика |
| `/arrma-claude-md-check` | проверить, есть ли в `CLAUDE.md` проекта критичные правила: сборка, тесты, запуск, папка задач, язык, STE, LSP, git, документация, запреты; ничего не меняет | путь к репозиторию |
| `/arrma-ste` или «по STE» | включить стиль письма STE до конца сессии; выключить: «без STE» | |
| `/arrma-eli5` | объяснить коротко и просто; без текста перепишет последний ответ | текст или тема |

Можно писать обычными словами: «перепроверь», «сделай план», «объясни как пятилетнему».

## Агенты

| Агент | Что делает |
|---|---|
| `arrma-gap-finder` | ищет ошибки и пропуски |
| `arrma-simplifier` | ищет, что убрать или упростить |
| `arrma-spec-reviewer` | сверяет работу с `requirements.md` |
| `arrma-finding-verifier` | опровергает находки остальных |

Руками их вызывать не нужно. Первых трёх запускает `/arrma-recheck`, потом отдаёт находки четвёртому.

- Агентам доступно всё, что есть в сессии: MCP, LSP, скиллы, консоль. Хуки из твоих настроек действуют и внутри них.
- Запрещено править файлы и запускать других субагентов.
- Агентам закрыты серверы `Claude_Docs`, GitHub, MongoDB, Playwright и Telegram. Закрыть ещё один: добавь `mcp__<сервер>` в `disallowedTools` в файле агента.

## Файлы задачи

Папка задачи берётся из `CLAUDE.md` проекта, иначе `docs/tasks/<задача>/`. Задача набора — это папка с `requirements.md`. Задачи старого формата проекта (`README.md`, `SUMMARY.md`, плоские заметки) набор не видит и не трогает. Если задачи набора лежат рядом со старыми, напиши в `CLAUDE.md` проекта, где они лежат и куда идёт то, что проект хранит в заметке задачи: индексы, `## MigrationPlan` и т. п. Обычно это отдельный раздел в `plan.md`.

| Файл | Что внутри | Кто создаёт |
|---|---|---|
| `requirements.md` | требования твоими словами: обязательно (R), ограничения (C), вне рамок (X); «Решения» — твои ответы на вопросы | анализ |
| `analysis.md` | задача, как сейчас, что менять, риски, вопросы Q1, Q2… | анализ |
| `plan.md` | этапы (последний — «Полный прогон»), «Не делаем», «Отклонено при перепроверке» | план |

Строки, по которым шаги находят друг друга после `/clear`:

| Строка в `plan.md` | Кто пишет | Зачем |
|---|---|---|
| `- База: <хеш>` | этап, до правок | перепроверка берёт дифф этапа от неё |
| `- [x] Сделано: …`, `- Файлы этапа: …`, `- Проверено: …` | этап, после проверки | статус, описание задачи и перепроверка читают итог отсюда |
| `- Стоп: …` | этап, если остановился | следующий запуск начинает с неё |
| `- Ждёт: …` в «Отклонено при перепроверке» | перепроверка | находка или вопрос, который решит твой ответ; «тесты не запустились» — ждёт исправной среды |
| `- Ждёт: документация …` в этапе | этап | правка документации, которую `CLAUDE.md` велит сначала согласовать |

Задач несколько — агент берёт незаконченную; когда таких несколько или ни одной, спрашивает. Агент не коммитит эти файлы, пока не попросишь.

## Тесты и документация

- **Тесты затронутого кода.** Этап и перепроверка гоняют сборку и тесты затронутого кода командой из `CLAUDE.md`. Все тесты — только если так велит `CLAUDE.md` и на последнем этапе «Полный прогон». Прогон с фильтром агент так и называет: «тесты этапа прошли (фильтр …)».
- **Живая проверка.** Запуск приложения, UI и смоук идут из поля «Проверка» этапа. План вписывает их туда, если `CLAUDE.md` требует их для этой области кода. Перепроверка повторяет «Проверку» после своих правок кода. Делает это главный агент: агентам набора закрыт Playwright.
- **Сбой среды.** Тест упал из-за среды (нет Docker, сети, VPN или базы) — это не баг и не находка. Агент не чинит код, а пишет, что не запустилось. Тест для бага должен падать на проверке теста, а не из-за среды. Признаки сбоя среды опиши в `CLAUDE.md` проекта.
- **Документация проекта.** Этап обновляет её сам и вписывает в «Файлы этапа», поэтому перепроверка её проверит. В итоге этапа есть строка «Документация». Если `CLAUDE.md` велит сначала предложить правку, агент предлагает её и пишет строку «Ждёт».
- **Файлы задачи.** Агент правит их без подтверждения. Пункты R и C — только с твоего согласия.

## Модели

Модель агентов и трёх скиллов задана по важности работы, остальное идёт на модели сессии:

| Кто | Модель |
|---|---|
| `arrma-gap-finder`, `arrma-finding-verifier` | последняя Opus |
| `arrma-simplifier`, `arrma-spec-reviewer` | последняя Sonnet |
| разведчики в `/arrma-task-analysis` | Sonnet |
| `/arrma-task-status`, `/arrma-task-summary`, `/arrma-claude-md-check` | Sonnet, в отдельном контексте |
| остальные скиллы | модель сессии |

Главный агент и встроенный `code-review` идут на модели сессии: это почти половина цены перепроверки. Дешевле всего делать `/clear`, переключаться на Sonnet и запускать `/arrma-recheck` оттуда.

Модель агента выбирается так: параметр `model` в вызове агента → поле `model` в файле агента → переменная `CLAUDE_CODE_SUBAGENT_MODEL` → модель сессии. Переменная только запасная и модели агентов набора не меняет (с Claude Code 2.1.251). А правило в памяти или `CLAUDE.md` проекта вроде «всегда передавай `model: sonnet`» их перебьёт: убери его или сделай исключение для `arrma-*`. На какой модели работает агент, видно в `/tasks`.

Поменять на один вызов: `/arrma-recheck model=sonnet effort=medium`. Модели: `opus`, `sonnet`, `haiku`, `fable`. Effort: `low`, `medium`, `high`, `xhigh`, `max`. На встроенный `code-review` параметр `model=` не действует: он идёт на модели сессии.

## Язык

Тебе в чат и в файлы задачи агент пишет на русском. Между собой агенты общаются на английском: так уходит примерно на 20% меньше токенов на тот же текст. Цитаты из кода и требований не переводятся.

## Разрешения

Скиллы задачи сами разрешают себе и своим субагентам читающие команды git (`status`, `log`, `diff`, `show`, `grep`, `ls-files`, `worktree list`, `rev-parse`) на время хода; `arrma-task-stage` ещё и `stash create` для снимка «Базы». Сборку и тесты разреши сам: пример в `settings.example.json`.

## Проверка на рабочей машине

План приёмки и доработки лежит в `ACCEPTANCE.md`.

## Необязательно

**Механическая сверка цитат** (нужен .NET 10 SDK). Без неё скиллы перечитывают цитаты сами.

```powershell
dotnet publish tools/check-claims.cs -o "$HOME/.claude/tools/check-claims"
```

Добавь в `CLAUDE.md` строку `Команда сверки цитат: dotnet "$HOME/.claude/tools/check-claims/check-claims.dll" <файл>` и разрешения из `settings.example.json`.

**Сводка по сессии** (нужен .NET SDK 8 или новее). Показывает по каждому агенту модель, ходы, токены и вызовы инструментов. Нужна для приёмки и чтобы видеть, кто тратит.

```powershell
dotnet publish tools/session-report -c Release -o "$HOME/.claude/tools/session-report"
dotnet "$HOME/.claude/tools/session-report/session-report.dll" <id сессии>
```

**Stop-хук для .NET.** Один раз возвращает агента к работе, если не проходят сборка с `-warnaserror` или быстрые тесты. Второй раз подряд не блокирует, чтобы агент мог остановиться и спросить.

```powershell
dotnet publish tools/stop-check.cs -o "$HOME/.claude/tools/stop-check"
```

Блок `hooks` из `settings.example.json` перенеси в `.claude/settings.json` проекта, подставив решение и фильтр быстрых тестов. Включай хук, только если проект до начала задачи собирается без предупреждений и тесты зелёные: иначе он будет срабатывать на каждом ходу. Проект без тестов хук считает прошедшим. Параллельные сессии с хуком держи в отдельных worktree.
