# План задачи

## Порядок

1. **Вход.** `requirements.md` и `analysis.md` из папки задачи. Анализа нет — предложи `/arrma-task-analysis`. Текст в аргументах — ответ на вопрос: запиши его в «Решения» в `requirements.md`. Остался вопрос из `analysis.md` без ответа в «Решениях» или пункт с `(?)` — задай его и остановись. `plan.md` уже есть — не пересоздавай: правь только затронутое, строки этапов и «Отклонено при перепроверке» сохрани.
2. **Этапы.** Самый простой путь к требованиям. Каждый этап:
   - собирается и проверяется сам по себе;
   - закрывает конкретные пункты R;
   - использует готовое в проекте, если оно есть (`file:line`);
   - трогает как можно меньше файлов;
   - в «Проверке» несёт живую проверку (запуск приложения, UI, смоук), если `CLAUDE.md` проекта требует её для затронутой области.
   Последний этап — «Полный прогон»: все тесты и смоук командами из `CLAUDE.md`, если они там есть; без правок кода и пунктов R, «Файлы этапа: нет». Ничего сверх требований. Сомневаешься, нужен ли шаг, — убери его.
3. **Запиши `plan.md`:**

```markdown
# План: <задача>

## Этап 1. <название>
- [ ] Что: ...
- Зачем: R1
- Файлы: ...
- Проверка: тест или команда, которая докажет, что этап сделан

## Не делаем
- ...

## Отклонено при перепроверке
- ...
```

4. **Упрощение.** Если просят упростить или сократить, сначала покажи таблицу «Что убираем | Какой пункт затронут | Что теряем». Пункт R или C убирай только с согласия пользователя и запиши это в «Решения» в `requirements.md`. Остальное убирай без вопросов.

## Итог

Этапы по одной строке, затем «Не делаем» одной строкой. Последняя строка: «Дальше: `/clear`, затем `/arrma-recheck` или `/arrma-task-stage`».
