# Анализ задачи

## Порядок

Если в папке задачи уже есть `requirements.md` и `analysis.md` этой задачи, не начинай заново: покажи открытые вопросы и продолжи с первого. Заново — только по прямой просьбе.

1. **Требования.** Запиши в папке задачи `requirements.md` словами пользователя:

```markdown
# Требования: <задача>

## Обязательно
R1. ...

## Ограничения
C1. ...

## Вне рамок
X1. ...

## Решения
- <дата>: что изменено и подтверждение пользователя
```

   Своё предположение помечай `(?)` и не считай требованием, пока пользователь не подтвердит.
2. **Факты.** Запусти субагентов параллельно, каждому одну область (задача на один-два файла — хватит одного субагента на всё):
   - код: где это работает сейчас, вход, вызовы, данные, похожие готовые решения в проекте;
   - документация и `CLAUDE.md` проекта;
   - история: `git log`, соседние ветки и worktree (`git worktree list`, `git log --all --oneline -- <пути>`).
   От каждого нужны факты с `file:line` и дословной цитатой. В задании каждому напиши: только чтение, команды по одной, без циклов, `|` и `cd`. Состояние репозитория не меняй.
3. **Проверка.** Открой каждый факт, на котором строится вывод, и убедись, что цитата стоит там. Документация и комментарии — утверждения: проверяй их по коду. Для главного вывода попробуй найти опровержение. Что не подтвердилось, убери или пометь «не проверено».
4. **Запиши `analysis.md`:**
   - `## Задача`: одна-две фразы.
   - `## Как сейчас`: факты с `file:line`.
   - `## Что менять`: где и что, без лишнего.
   - `## Риски и неизвестное`.
   - `## Вопросы`: с номерами Q1, Q2…; только те, без ответа на которые нельзя идти дальше.
   - `## Отклонено при перепроверке`: пусто, заполняет `/arrma-recheck`.

## Модель субагентов

Субагентам из шага 2 передавай параметры `model: sonnet` и `effort: high`: они только собирают факты, а ты перепроверяешь их в шаге 3. Если в аргументах есть `model=<opus|sonnet|haiku|fable>` или `effort=<low|medium|high|xhigh|max>`, передай вместо них эти значения.

## Итог

Не больше 10 строк: суть, главные риски, файлы задачи. Есть вопросы — закончи первым вопросом, простыми словами. Вопросов нет — последняя строка: «Дальше: `/clear`, затем `/arrma-recheck` или `/arrma-task-plan`».
